# Senatordle

The daily U.S. senator guessing game. Each day has two rounds, **Normal** and **Hard**. Each round has a mystery senator and about 10 handwritten clues, going from vague to specific. After each clue you can guess or skip.

## Running it

It's a static site with no build step and no dependencies.

- **Locally:** open `index.html` in a browser, or serve the folder (`python -m http.server`) and go to `http://localhost:8000`.
- **Hosting:** the site is hosted on GitHub Pages (see [Deploying](#deploying)).

## Project layout

```
index.html          Page markup: title screen, chart, guess panel, dialogs
css/style.css       Styles (light and dark)
js/config.js        Launch date, rounds, state and party lists
js/storage.js       localStorage: saved games, stats, flags
js/search.js        Senator search box (name match, photos, party/state tags)
js/chart.js         Senate seating chart: geometry, seat bars, title/play screen layouts
js/app.js           Game controller: puzzle, rounds, screens and animation, stats, sharing
data/senators.js    Senator database (generated by tools/fetch_senators.py)
data/puzzles.js     Daily puzzles keyed by date
images/             Generic_Image.png placeholder; images/senators/ holds downloaded photos
tools/              fetch_senators.py + senator_overrides.json
```

## Adding data

### Senators: `data/senators.js` (generated)

`tools/fetch_senators.py` builds this file. It covers everyone who served in the Senate on or after **January 1, 1990**, including senators already in office that day.

```
python tools/fetch_senators.py                    # fetch data, download missing photos
python tools/fetch_senators.py --refresh-images   # download every photo again
python tools/fetch_senators.py --no-images        # data only
```

- **Names, states, parties** come from Wikidata, the structured database behind Wikipedia's infoboxes. It has one record per senator per Congress, with seat and party attached.
- **Photos** come from the Wikipedia API (the article's main image), falling back to Wikidata's image. They are saved as 256px-wide thumbnails in `images/senators/`.
- The script needs only the Python standard library.
- **Don't edit `data/senators.js` by hand.** The next run overwrites it. Put fixes in `tools/senator_overrides.json`, keyed by Wikidata id (the `qid` field), e.g. `{"Q538868": {"party": ["D", "I"]}}`.
- Each run prints a check: about 100 senators serving on January 4 of every year since 1990.

Record format:

```js
{ id: "ted-cruz", name: "Ted Cruz", state: "TX", party: ["R"], start: 2013, aliases: [...], sortName: "Cruz",
  image: "images/senators/ted-cruz.jpg", imageSource: "https://en.wikipedia.org/wiki/File:...", wiki: "...", qid: "Q2036942" }
```

`id` is the name as a slug (`ted-cruz`); senators with the same name also get the state (`-tx`). `party` lists every Senate party in date order (`["D", "I"]` for Manchin). No `end` means the senator is still serving. A senator without an `image` shows `images/Generic_Image.png`.

**Photo licenses:** most official portraits are public domain, but some Wikipedia photos are CC BY-SA, which requires credit. `imageSource` links to each file's page, which shows its license.

### Puzzles: `data/puzzles.js`

```js
'2026-11-14': {
  normal: { answer: 'ted-cruz', clues: [
    'This senator is a man.',
    { text: 'This senator is a member of the Republican Party.', reveals: ['party'] },
    ...
  ]},
  hard: { answer: 'marsha-blackburn', clues: [ ... ] },
}
```

- Dates use the player's local date. A day with no entry shows a "No puzzle today" screen.
- Search results show a party/state tag, e.g. `Jon Ossoff (D-GA)`. `reveals: ['state' | 'party']` marks the clue that gives that fact away. Once the player reaches that clue, the tag drops it (`(GA)` or `(D)`), and if both are revealed the tag disappears.
- `category` (optional) is a short label like `"Previous Job"`. Locked clues show it instead of "Locked". It's there to support the planned "chosen hints" feature.

When the page loads it checks the data and prints problems to the browser console, such as an unknown answer id, a duplicate id or a bad state code.

## Gameplay rules

- You start with clue 1. A wrong guess or a skip reveals the next clue.
- **Skip** and **Give up** must be pressed and held (`holdDuration` in `js/config.js`, 800 ms by default).
- A wrong guess or a skip on the last clue ends the round, and so does **Give up**.
- Your score is the clue number you solved it on.
- Progress and stats are saved in localStorage. Stats and streaks are kept separately for each round, and only today's puzzle counts toward them.
- `?date=YYYY-MM-DD` plays a past puzzle (archive). It doesn't count toward stats, and future dates aren't allowed.

## Deploying

The site is served by GitHub Pages straight from the `main` branch. There's no build step.

1. The repository must be public (required for Pages on a free account).
2. On GitHub: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, then choose `main` and `/ (root)` and save.
3. After a minute the site is live at `https://dmillslagle.github.io/senatordle/`. Every push to `main` redeploys it.

`.nojekyll` (an empty file) tells Pages to serve the files as-is instead of running them through Jekyll.

To use a custom domain, add it under **Settings → Pages → Custom domain** and follow GitHub's DNS instructions. HTTPS is set up automatically.

Puzzle answers ship to the browser in `data/puzzles.js`, and in a public repo every committed puzzle is visible. Consider pushing puzzles only a few days ahead.
